## Deployment

### Podman Compose

```yaml
services:
  couchdb:
    image: "ghcr.io/daemonless/couchdb:latest"
    container_name: couchdb
    environment:
      - PUID=1000  # User ID for the application process
      - PGID=1000  # Group ID for the application process
      - TZ=UTC  # Timezone for the container
      - COUCHDB_USER=admin  # Administrator username created on first start
      - COUCHDB_PASSWORD=changeme  # Password for COUCHDB_USER (hashed into /config/etc/local.ini on first start; if unset, a random password is saved to /config/admin_password)
      - COUCHDB_SINGLE_NODE=true  # Automatically create _users and _replicator system databases on startup (set false for multi-node cluster setup)
      # - COUCHDB_SECRET=  # Cookie authentication signing secret (generated and persisted in /config/etc/local.d/10-secret.ini if unset)
      # - NODENAME=  # Erlang node host or IP for multi-node clustering (-name couchdb@NODENAME)
      # - COUCHDB_ERLANG_COOKIE=  # Shared Erlang distribution cookie written to /config/.erlang.cookie for clustering
    volumes:
      - "/containers/couchdb:/config"
    ports:
      - "5984:5984"
    # always (not unless-stopped) so FreeBSD's podman rc.d auto-starts it at boot
    restart: always
```

Save as `compose.yaml`, then run `podman-compose up -d`.

## First run and Fauxton UI

CouchDB 3.x requires an administrator account. Set `COUCHDB_USER` and
`COUCHDB_PASSWORD` before first start; CouchDB hashes the password in place
in `/config/etc/local.ini` on boot. If `COUCHDB_PASSWORD` is omitted,
a random password is generated on first start and written to
`/config/admin_password` (mode `0600`).

Sign in to the Fauxton web interface at `http://<host>:5984/_utils/`.

## Configuration and persistence

Both database shards (`/config/data`) and configuration files
(`/config/etc/local.ini`, `/config/etc/local.d/*.ini`, and
`/config/etc/vm.args`) live under `/config`, so settings changed through
Fauxton or `/_config` (such as CORS rules for PouchDB or Obsidian LiveSync)
persist across container upgrades without extra bind mounts.

`COUCHDB_SINGLE_NODE=true` is enabled by default so standalone deployments
create `_users` and `_replicator` automatically on first boot. For a
multi-node cluster, set `COUCHDB_SINGLE_NODE=false`, `NODENAME`, and a
shared `COUCHDB_ERLANG_COOKIE`, and publish ports `4369` (`epmd`) and
`9100` alongside `5984`.
